## Why

Nothing in this fork names the OpenSpec version its artifacts are written for, there are no OpenSpec skills in
the repository (changes were written by hand, so the one archived change has no `.openspec.yaml`), and nothing
validates `openspec/` in CI. `openspec/config.yaml` carries only `context`, so the CLI injects no project rules
into specs, tasks, apply or archive.

## What Changes

- `openspec/cli.pin`: the one OpenSpec CLI version for this repository (`1.16.0`); CI runs that exact version.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify),
  generated by the pinned CLI for Claude Code (`.claude/skills/`) and Codex (`.agents/skills/`), committed.
  `.claude/` and `.agents/` become infrastructure paths.
- A new `openspec` CI job: `openspec validate --all --strict`, no main spec with the archive placeholder
  Purpose, `.openspec.yaml` in every active change, skills generated by the pinned version, no unticked
  non-`[human]` task in an archived change.
- `openspec/config.yaml`: `rules.specs`, `rules.tasks`, and `operations.apply` / `operations.archive` guidance
  that points at the steps of `AGENTS.md`.
- `AGENTS.md`: the pin, how to bump it, the skills, and the new check.

## Capabilities

### New Capabilities
- `openspec-tooling`: the pinned OpenSpec version, the generated skills and the CI validation of `openspec/`.

### Modified Capabilities
None.

## Impact

Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`,
`.github/infra-paths`, `AGENTS.md`. No code commit, so the build key does not move. The existing archive is
left as it is.
