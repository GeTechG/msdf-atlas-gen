## Purpose
Keep OpenSpec in this fork on one pinned CLI version, with skills generated by it and every rule of `openspec/` checked in CI.

## ADDED Requirements

### Requirement: One pinned OpenSpec version
`openspec/cli.pin` SHALL hold the one OpenSpec CLI version of the repository, as a single line, and CI SHALL run the OpenSpec CLI of exactly that version.

#### Scenario: CI runs the pinned CLI
- **WHEN** `openspec/cli.pin` reads `1.16.0`
- **THEN** the `openspec` CI job runs `@fission-ai/openspec@1.16.0`, whatever version is current on npm

### Requirement: Skills match the pin
The committed OpenSpec skills in `.claude/skills/` and `.agents/skills/` SHALL be generated by the pinned version; CI SHALL fail when the `generatedBy` of any of them differs from `openspec/cli.pin`.

#### Scenario: Pin bumped without regenerating skills
- **WHEN** a commit changes `openspec/cli.pin` to `1.17.0` and leaves skills with `generatedBy: "1.16.0"`
- **THEN** the `openspec` CI job fails and names the stale skill files

### Requirement: Specs and changes validate strictly
CI SHALL fail when `openspec validate --all --strict` reports any problem.

#### Scenario: Invalid delta
- **WHEN** an active change has a requirement without a scenario
- **THEN** the `openspec` CI job fails

### Requirement: Main specs have a real Purpose
CI SHALL fail when a main spec's Purpose starts with `TBD - created by archiving change`.

#### Scenario: Archive placeholder left in place
- **WHEN** archiving a change creates `openspec/specs/x/spec.md` with the placeholder Purpose and nobody rewrites it
- **THEN** the `openspec` CI job fails and names that spec

### Requirement: Active changes are created by the CLI
CI SHALL fail when a directory of `openspec/changes/` other than `archive` lacks `.openspec.yaml`.

#### Scenario: Change written by hand
- **WHEN** `openspec/changes/x/` holds `proposal.md` and `tasks.md` but no `.openspec.yaml`
- **THEN** the `openspec` CI job fails and names `x`

### Requirement: Archived changes have no open agent tasks
CI SHALL fail when a `tasks.md` of an archived change has an unticked task not marked `[human]`.

#### Scenario: Unticked agent task archived
- **WHEN** an archived `tasks.md` has `- [ ] 2.1 Update the README`
- **THEN** the `openspec` CI job fails and names the line

#### Scenario: Unticked human task archived
- **WHEN** an archived `tasks.md` has `- [ ] 3.1 [human] Check the atlas on a device`
- **THEN** the check passes
